# 大文件与批量资料拆解

分片上传使用8MiB单片，默认单文件上限1GiB，支持重试与查询已收分片，文件合并采用流式读写。批量文件可并发上传，结构提取在独立Python进程排队执行，不阻塞前台API。

本地解析覆盖PPTX、DOCX、PDF文本、常见图片、文字文件和安全筛查后的ZIP。PDF需要pypdf，图片预览需要Pillow；Windows启动脚本可使用Codex提供的Python，部署时通过QISHU_PYTHON指定解释器。旧版二进制.ppt需先转换为.pptx，未提供转换器时明确标记，不假称已理解。

结构拆解产生来源页码、文字和媒体卡片，属于待确认草稿。扫描PDF、纯图片、音视频的语义识别仍需要OCR、ASR或视觉模型。只有真实渠道返回后才可记为AI理解完成。管理员确认后才能通过业务适配器发布。

容量上限、成功上传、结构提取成功、AI理解、人工确认和发布是不同状态。大文件速度取决于网络、页数、媒体数量、解析和模型资源；不能仅以配置1GiB就宣称真实1GiB文件已通过全链路性能验收。

安全措施包含身份访问控制、源文件私有、分片计量、上传并发限制、压缩路径检查、展开大小及页数限制、外部实体拒绝、解析独立进程和超时。源文件不直接发布，业务确认的卡片素材才可进入公开展示。

写操作需要`ingestion:write`，跨账号读取原件需要`ingestion:read`；确认公开还需目标内容资源的写入权限。`*`为平台最高权限。AI理解请求立即返回202，前台轮询`understanding`任务；按批次归类文字，部分媒体尚待识别时标记partial。理解中不允许编辑覆盖，失败保留原结构。

当前每份文档首批最多300页、每任务500卡片；Word文本首批30万字符，单个文档XML上限16MiB，压缩展开总量上限4GiB。超限需要分批，不代表整份文件完成语义理解。Linux解析进程另限制地址空间，Windows使用格式边界与超时，不冒充已实现系统Job Object内存隔离。
