版本：V2.4 微信首发版（含本轮大文件补充）  
日期：2026年11月10日  
需求负责人：何炜  
交付对象：产品、设计、开发、运营及技术合作方  
目标：争取2026年11月28日前正式上架微信小程序并可实际使用。

本版汇总本轮最新确认的需求，覆盖商业目标、双角色界面、后台配置、AI基础能力、Demo删改、验收和上线条件。旧版本与本版不一致时，以本版为准。“待确认”不是已经批准的决定。文档完成不代表软件开发、真实模型联调或微信审核已经完成。

## 1 商业目标与平台边界

平台面向女装店主和厂家。对店主的核心价值是获取资讯、找到适配货源、获得店铺经营诊断；对厂家的核心价值是展示、主动找客户、获得联系意向和回访依据。平台官方组织信息、管理内容和资质、配置展示与商业权益，持续改进匹配效果。

平台不承接商品交易。货源报价、起批量、混批、供货状态和交期仍需展示；商品下单、商品支付、交易退款、分账和结算不进入首发。

商业化包括厂家主动获客额度升级，以及开屏、置顶、轮播和资讯推广等展示服务。免费额度和付费权益由平台配置，收费金额和有效期待定。**首发在线下完成权益购买，由平台确认后在后台开通，小程序用于查看和使用权益，不提供在线购买或续费收款。后期可增加平台服务权益的在线购买、续费和支付。** 无论是否增加权益支付，货品下单、订货、货款支付和商品交易链路始终不做。

首发成功先验证：店主能否找到合适货源并发起联系；厂家能否获得经回访确认的需求；诊断建议能否被店主使用；内容与推荐能否促成再次访问。没有真实运营基线，不虚构增长、收入或转化率承诺。

## 2 首发平台与双角色信息架构

一期只做微信小程序。网站用户界面、厂家经营后台和平台运营后台按各自使用场景适配；抖音小程序及独立 App 后续评估。底层账号、数据和业务服务可复用，不以重做所有业务为扩端前提。

### 2.3 入口归属与内容生产

厂家和店主的“我的”均包含创作中心。资讯及货源相关页面也要有发布入口，进入与当前角色、页面场景对应的表单；不能要求用户每次返回“我的”才可发布。店主发布资讯、经验或适用的拿货需求，厂家发布货源、订货会及资讯；具体类型的权限可配置。

厂家、店主、平台官方都可以贡献普通分享或专业制作内容，UGC和PGC表示生产方式，不与某个角色强行绑定。记录作者、主体、生产方式、来源、媒体及审核状态。

订货会归属货源，不设独立一级入口。多模态、模型路由、推荐和知识检索为共用底层能力，不设独立一级栏目。独立同行圈和经营工具暂缓，但内容发布及共用处理能力保留。

## 3 账号权限与经营资质

| 身份 | 业务权限 |
| --- | --- |
| 游客或已登录未认证用户 | 有限预览、登录、提交资料、查看审核进度；预览的具体字段待冻结 |
| 认证店主 | 使用店主四个入口；查看正式开放资讯和货源、联系厂家、创作发布、诊断及管理自己的记录 |
| 认证厂家 | 使用厂家四个入口；管理本主体内容和经营资料，按权益主动获客、回访 |
| 平台最高管理角色 | 拥有全平台业务管理权限，包括角色授权、审核、内容、展示位、广告、推荐干预、额度权益、知识库、模型配置和统计 |

平台最高管理者可配置其他后台成员的权限，关键操作记录操作者、对象、时间和变更前后内容。厂家仅管理本主体私有数据；店主仅访问自己的非公开诊断资料。后端统一鉴权，不能靠前端隐藏按钮实现隔离。

店主或厂家认证流程：微信登录 → 经用户同意验证手机号 → 未认证账号 → 上传营业执照 → AI预审 → 人工终审 → 经营偏好初始化 → 进入对应角色界面。

- 微信登录用于建立平台账号，头像、昵称和手机号按微信现行授权能力分别处理，不能默认读取全部微信资料。
- 手机号需要防空号或失效号码时，应评估实时验证方式；一次验证不代表号码始终可联系。具体能力资格及费用待确认。
- AI识别企业名称、信用代码、经营范围等字段，核对填写差异，提示图片不清、缺项、重复等疑点；人工负责终审并记录原因。
- **经营范围包含服装批发或服装零售，即满足平台行业准入要求，不另要求实拍证明是否经营女装。** 证照与填写信息的一致性审核仍保留。
- 状态包含待提交、AI处理中、待人工审核、待补充、通过、驳回；支持补充、重提及变更后复核。
- 对外显示“已完成资质审核”并说明范围。不能将其解释为平台担保所有内容真实、认定实际主营女装或保证商品质量。
- 营业执照、非公开手机号及原始诊断资料不对普通用户公开，访问按授权留痕，说明外部AI服务参与处理的范围。

### 3.1 平台管理员授权与微信绑定

平台最高管理者在电脑网页后台录入授权手机号，分配角色和具体权限，形成待绑定的管理员记录。被授权人通过本人微信登录并完成手机号验证或绑定确认后，后端把已验证的平台账号与管理员授权关联；再次登录加载对应管理入口。

授权手机号、本人微信登录身份、绑定状态、角色和有效状态分别记录，支持停用、撤权、改绑与操作审计。不能把手填微信号、昵称或手机号字符串直接当作绑定已验证；普通用户不得因知道某个授权手机号而取得管理权限。

电脑端微信登录采用平台支持的扫码或授权确认方式，与手机端账号建立可信关联；具体接入资格和凭证在实施时核定，不把小程序登录接口直接当作网页微信登录。

### 3.2 认证后选择四到十个经营偏好标签

进入个性化体验前，认证用户至少选四个、最多选十个标签。选择数量有明确提示，支持后续在“我的”修改；标签字典、分类、名称、顺序、显隐由后台维护，不能把标签写死在客户端。

标签覆盖经营风格、目标客群年龄、零售或拿货价格带、门店体量、采购方式、供货条件和资讯需求。例如韩系、特定客群、小单快返、支持并单、支持按需做货等；这些是经营偏好或供货条件，不代表平台承接订单和商品交易。

面积、客单价等实际数值仍可存为结构化资料，再映射适用标签；不能让十个标签替代全部门店档案。不同角色使用适用的标签：店主描述自己的经营及拿货需求，厂家描述供货特征和目标客户条件。

用户选择非个性化浏览时应有可用路径，不因关闭个性化而继续按其画像排序。个性化开关、标签修改和清除兴趣反馈须在服务端和推荐结果中真正生效。

## 4 资讯与创作中心

资讯支持图文卡片、视频、音频及适合的组合呈现，支持频道、搜索、详情、收藏、来源说明和推荐。沿用现有Demo中有用的信息结构与瀑布流思路，重做真实数据与审核。

两端创作中心管理本人或本主体的素材、草稿、提交审核、驳回修改、已发布、下架及删除内容。厂家额外管理货源和订货会。官方可编辑平台内容并处理违规或过期内容，介入操作需留痕。

身份审核与内容审核分开，已认证不代表免审发布。资讯记录来源与发布时间，历史内容不能冒充实时消息；广告推广、官方整理和用户分享应能区分。举报、投诉、反馈与处理结果可查询。

## 5 货源广场与订货会

### 5.1 六项组合筛选

六项为并列条件，不是六层菜单：风格、产地、品类、拿货价格带、起批量、供货状态。

| 条件 | 要求 |
| --- | --- |
| 风格 | 标准名称与别名由后台维护，支持扩展和纠错 |
| 产地 | 将原“发货地”主筛选改为“产地”；按省市和产业带组织，实际发货地可另存 |
| 品类 | 大类与子类可扩展，不把面料和尺码混作同一类目 |
| 拿货价格带 | 使用批发单价，区分零售价；区间、显示名称和顺序可配置 |
| 起批量 | 数值、单位与混批条件分别保存，件、手、包等不能直接混算 |
| 供货状态 | 现货、预售；交期、库存说明及更新时间在详情体现 |

产地字典首批覆盖已明确的杭州、濮院、平湖、海宁、昆山、常熟、大连、即墨、武汉、广州、深圳等地区，结合已有资料和运营录入继续丰富；不能声称已经穷尽全国所有产地、品类或风格。

全部分类、区间、顺序与可见性由后台维护。支持条件组合、重置、无结果提示和返回时保留条件。价格、产地、起批量缺失时标待补充，AI不得猜测补齐。

货源详情记录名称、媒体、厂家、风格、产地、品类、拿货价、起批量、混批、供货状态、交期、售后说明及更新时间；发布必填字段在开发前冻结。没有关键拿货条件时，不得以完整货源对外发布。

### 5.2 订货会

订货会在货源内部展示。顶部支持两到三张招募图轮播，建议默认三秒切换；图片、顺序、间隔、生效时间、受众和跳转目标由后台配置，支持手动切换。

厂家可以创建草稿、编辑、提交，平台负责审核、置顶、下架和排期。详情包括主办方、主题、地点、时间、目标人群、货盘与参加条件。参加登记或表达意向不收款；启用名额限制时，后端防重复和超额登记。

### 5.3 联系厂家与回访

详情提供清楚的联系入口，按微信实际允许的能力展示微信号、二维码或其他获批方式；不能预先承诺一键直接添加个人微信好友。

分别记录查看、点击联系、复制微信号、查看二维码、用户或厂家反馈和回访。点击不等于已经加好友，复制不等于有效客资，更不能自动记为成交。真实好友状态需要可用的官方集成或明确标注的人工反馈。

厂家只查看本主体的联系意向及获准提供的用户信息。回访建议包含待回访、已回访、待跟进、无效或关闭，具体状态待冻结。

## 6 厂家找客户与商业权益

“找客户”是厂家首发一级入口，参照现有Demo的列表与店主资料对照方式。支持公开客户条件筛选、拿货需求、推荐、收藏、主动联系和回访记录。店主私有证照、非公开联系方式及诊断报告不能直接开放给厂家。

提供每日免费主动获客额度，用户举例为十次。**十次为示例初始值，额度必须后台可编辑**，可按厂家主体、身份或权益设置免费量、付费增加量、有效期、生效时间和停用状态。

计次建议按“首次成功向不同店主发起联系”计算，不按浏览或普通搜索扣次；具体计次动作、去重周期、刷新时间、是否结转待确认。操作前显示剩余额度，后端统一处理并发、重试、扣减和额度日志。失败不能乱扣，推荐接口或多个操作人不能绕过主体额度。

超出免费额度可付费获得更高权益。**首发采用线下购买、平台确认、后台开通的方式**，不接在线权益支付。厂家可查看当前权益、剩余额度、到期时间和续费联系方式；需要升级或续期时联系平台线下办理。

## 8 平台共用AI与推荐基础能力

### 8.1 多模态处理与生成

文字、图片、视频、音频的输入、理解和输出均纳入能力范围。支持文字生成、图片生成、视频生成、语音识别ASR、语音合成TTS和OCR，并服务厂家、店主、平台官方的发布、诊断和咨询场景。

处理流程为上传并保留原件、识别理解、字段提取归类、生成业务草稿或回答、确认及审核、发布或使用。比例不同的素材生成适配封面，详情可完整查看；不得把商品拉伸失真或凭空改变实物信息。

长任务采用异步处理，展示上传、排队、处理、待确认、完成、失败及重试状态。文件大小、音视频时长、并发、内容审核和费用上限在联调前明确。生成内容须按实际要求标识；模型生成不等于事实核实。

### 8.2 多模型路由与密钥管理

平台后台建设可扩展的供应商、模型和能力注册表，支持新增、编辑、测试、启用、停用及任务路由，不在页面写死单个模型。按任务能力、输入类型、输出类型、可用性、费用、时延及数据处理限制选择渠道。

候选包括DeepSeek、Kimi、混元、Gemini、GPT及GPT图像系列、MiniMax、阶跃星辰、xAI的Grok，以及Nano Banana等用户提及的图像、视频和文本系列。原话中的“C-Dance”“Image2.5、6”“GPT图像2.6”“MiniMax H3／A七三”等具体名称或型号存在语音转写歧义，须按官方可调用接口核定，不能凭转写擅自确定版本，也不能假设所有品牌都支持同一种接口。

平台官方在后台配置API Key及必要参数；密钥服务端加密保存、前端脱敏，支持轮换和停用，禁止进入客户端包、公开仓库或普通日志。密钥输入、修改和连通性测试仅授权管理者操作。

路由包含能力匹配、流式或异步适配、超时、重试、限流、用量与费用记录、故障切换。不能把图像模型发给不支持图像的渠道，不能在未告知或未获准时将私密资料切往另一个处理方。默认降级、预算和区域限制待配置。

**预留输入框不算已经接入。** 按最终启用清单验证真实请求、结果、错误和费用；未配置、未授权或测试失败的渠道明确标为不可用。架构支持扩展多家模型，不承诺任意未来型号无需适配即可使用。

### 8.3 分层知识库与系统提示词

平台官方上传底层知识、方法论和案例，配置诊断及咨询的系统提示词、任务模板、检索策略和输出格式，保留版本、预览、评测、发布及回退记录。这些配置和私有知识库管理界面不向厂家、店主开放。

系统提示词按平台规则、业务任务和供应商或模型模板分层，支持Gemini等不同模型的系统指令格式，由适配层转换。只有平台授权管理员可编辑和发布；普通店主、厂家只能提交自己的问题、资料和获准设置的偏好，不能修改平台系统提示词。用户知识库中的文字也不能覆盖平台权限和系统规则。

厂家和店主可以建立自己的私有知识库。检索按平台授权知识、本账号或本主体私有知识、当前任务资料组合，先校验访问权限再检索；不得跨厂家、跨店主串库。是否允许成员共享由授权管理者设置。

前端只获取允许展示的答案、摘要或依据，不提供平台私有库下载、系统提示词或密钥。私有资料不能仅靠一句提示词保密：源文件访问、检索范围、日志与输出检查都需控制，测试越权查询和诱导泄露。

用户提问和反馈可进入改进流程：收集反馈、记录失败类型、在授权范围内脱敏整理、人工审定、知识或提示词版本更新、回归评测、发布。未经授权不能把用户私密资料汇入公共库或用于模型训练。

知识入库、提示词优化、模型微调和蒸馏是不同工作。模型训练或蒸馏需要合规样本、服务商能力、成本和离线评测；不能宣传为每次问答都会让外部模型自动学习。需保留错误纠正、样本删除及版本回退路径。

### 8.4 双塔推荐与千人千面

**基于本站行为的个性化推荐与真实双塔能力是明确开发要求**，服务资讯、货源及适用的客户匹配场景，不设独立一级入口。千人千面是效果目标，双塔是召回方法，个性化推荐包含召回、排序和反馈，不是三套各自独立的算法。

以平台账号关联经告知和必要授权采集的曝光、搜索、点击、前台有效停留、收藏、联系意向及不感兴趣反馈，结合主动填写的风格、产地、品类和预算等更新偏好。后台挂机、重复事件和误点不能当成有效兴趣。不得把微信外部行为或未授权资料当作本站画像来源。

推荐分三层建立和更新：

| 层级 | 依据与用途 |
| --- | --- |
| 第一层 初始偏好 | 根据认证后的四至十个标签和已填账号或门店资料，为第一次进入资讯、货源等界面提供冷启动推荐 |
| 第二层 站内行为 | 根据曝光、搜索、点击、有效停留、收藏、联系及不感兴趣等行为更新偏好，避免只依赖最初标签 |
| 第三层 授权融合 | 将初始标签、账号与门店资料、站内行为和获准用于推荐的知识摘要结合，改善内容、货源及适用客户匹配 |

第三层只能使用经过授权、与经营推荐相关的特征或摘要，不把整份私有知识库、执照或诊断原件自动送入公共推荐训练。用户私有知识仍按账号或主体隔离，后台记录特征来源、用途与撤回后的处理方式。

双塔须有用户侧表示、内容或货源侧表示、向量索引和召回服务，以及训练或适用预训练模型接入、模型版本和更新流程。召回后结合匹配、时效、质量、去重、多样性和运营策略排序。仅画架构图、保留接口、随机换序或改文案不能算真实推荐交付。

新用户与新内容缺少行为时，使用已填条件、内容属性和已审核候选冷启动，并设置探索位；该保底机制不能代替要求建设的双塔。效果随真实数据评估，不承诺某一提升比例，不用演示数据冒充生产效果。

候选先做审核和可见权限过滤，再计算匹配。营业执照、私密联系方式及诊断原件不得进入公共推荐结果。用户能关闭个性化推荐、选择非个性化浏览、调整偏好或反馈不感兴趣；商业推广与自然推荐区分。

运营可配置推荐位、季节与产地权重、人工置顶、探索比例、隐藏及黑白名单。验收分别检查事件链路、真实模型调用、画像改变后的结果变化、冷启动、故障降级、权限过滤和留出样本或灰度效果。

### 9.1 全站展示配置

对已经建设的页面、频道、模块、展示位、分类、按钮文案和媒体，提供草稿、预览、发布、生效时间、显示、隐藏、排序、归档或删除能力；按角色、季节和适用受众配置。配置发布后按约定缓存时效生效，记录版本并可回退。

例如春夏可把广州、深圳相关入口调前，将平湖、海宁相关入口后置或隐藏；这是可配置的运营策略，不是对这些产地生产能力的固定判断。隐藏筛选项不等于删除历史货源的产地字段，删除被引用分类时需处理关联数据。

“全站可配置”指已建设模块和展示位，不等于可以后台任意执行代码。新增页面类型、改变原生小程序配置或新增系统能力，仍可能需要开发、发版和平台审核；必要的返回、隐私及账号控制不能因错误配置导致整体不可用。

开屏应可按要求关闭或跳过，不阻断基本使用；推广标识清楚，投放内容和跳转需审核。商业推广不能伪装成自然推荐或资质背书，权限与审核优先于付费排序。统计曝光、点击、去重用户和可核对的联系意向，不虚构成交回报。

## 10 开发原则与跨端返回体验

结构为角色化用户端、厂家管理界面、平台运营界面、共用业务后端、数据库和文件存储。首期按一个代码工程组织业务模块，但运行隔离不能只靠分文件：前台请求、管理操作及AI、转码、训练等耗时任务分配独立执行资源或工作进程，按需使用队列。数据中台首版体现为统一模型、事件、服务接口和统计，不额外堆一套复杂系统。

- 模块化与故障隔离：明确账号、审核、内容、货源订货会、客户权益、诊断、模型路由、知识库、推荐和展示配置的边界。单模块异常、停用或升级不得拖垮无关模块，用户端应保持可导航及其余可用业务；实现要求和故障验收见下文。
- 轻量开发：简单实现优先，避免重复封装和为未知需求引入框架；代码清楚可维护，不以压缩行数为目标；保留必要鉴权、错误处理、日志与测试。
- 变更安全：关键路径回归验证，配置与发布可回退。不能保证任意改动绝不影响其他模块，但必须控制、验证并说明影响范围。
- 字号与设备：读取微信字号设置，卡片、表单和按钮能随文字增长或换行；验证苹果、安卓、微信鸿蒙和平板的标准、中间和最大字号，不能只靠窗口缩放。

### 10.1 故障隔离与功能停用

目标是局部故障局部处理、功能停用不影响其他业务，禁止因单块组件报错、接口超时、AI长任务或错误配置造成整个用户端白屏、卡死、无法返回或无限等待。

前端按业务区域隔离错误和加载状态，各模块请求设置合理超时、独立重试及取消；不把所有模块绑定为一个必须全部成功的加载链路。后端按模块限制并发和资源，持续失败时暂停向故障依赖请求，避免重试风暴；高风险耗时任务与前台服务隔离，不能因一个任务耗尽全部资源。

| 异常或操作 | 必须保留的体验及处理 |
| --- | --- |
| 推荐服务或双塔模型异常 | 切换到可用的已审核内容或非个性化排序，资讯、货源、搜索和导航继续可用；不伪称仍在使用故障模型 |
| 某个AI渠道异常 | 仅在能力和数据授权匹配时切换可用渠道；否则显示该任务稍后重试，保留输入，不阻塞资讯及货源 |
| 店铺诊断、OCR、音视频任务异常 | 问题限制在对应任务，记录状态和失败原因，支持恢复或重试；不触发整页或全站不可用 |
| 广告、轮播或非关键展示异常 | 跳过异常素材或使用有效配置，不阻断进入小程序和基本操作 |
| 管理后台不可用或正在维护 | 用户端通过独立服务和已发布配置继续提供可用内容；不依赖管理员页面在线才可浏览 |
| 新配置错误 | 发布前校验；用户端使用最近有效版本，配置失败不清空整站，支持回退 |
| 平台停用或下架某功能 | 同步调整其入口和服务开关，停止新任务；处理中任务按约定完成、取消或恢复，不静默丢失；直接访问旧链接有明确说明和返回入口 |
| 一个业务模块发布或回退 | 外部接口保持兼容，旧客户端仍能处理结果；不直接删除仍被引用的公共资源或历史数据 |

功能开关、页面可见性、服务状态分别管理：隐藏入口不等于停止服务，停止服务也不能误删其他模块需要的数据。错误提示应可理解，允许返回和重试，不能把整站维护页作为每个局部故障的默认处理。

共享数据库、登录服务、网络或整体基础设施中断时，相关真实读写可能不可用。此时保留页面骨架、导航、输入草稿及可安全展示的有效缓存；权限无法确认时不得用缓存绕过鉴权，更不能把失败提交显示为成功。更高等级的持续可用需要配套备份、冗余、健康检查与恢复资源，按实际部署和预算验证，不能承诺任何故障下所有功能都完全正常。

验收必须主动模拟推荐超时、AI渠道失败、素材不可用、后台维护、功能关闭、错误配置及任务进程异常，分别检查其他模块、返回、草稿和服务恢复。只看正常状态页面不能证明已经完成故障隔离。

### 10.2 跨端返回

返回规则覆盖小程序、网页前台、厂家后台和平台后台：

1. 从列表进入详情，再返回原列表，保留筛选、页签、分页和滚动位置，不无故跳首页或刷新清空。
2. 按平台原生页面栈与返回方式实现。苹果的边缘返回手势与安卓、鸿蒙系统返回分别验证，不强制所有设备统一左滑。
3. 弹层、全屏预览等临时视图优先关闭；不能一次返回就直接退出整个业务。
4. 无历史的分享或直接打开详情，有明确的上级入口；一级栏目切换和详情返回分开处理。
5. 网页支持浏览器前进后退及页面内返回，后台抽屉或详情切换不应使整页意外下跳；未保存编辑有草稿或必要提示。
6. 不用覆盖全部滑动事件的方法破坏正常滚动、轮播或系统手势。返回后没有重复弹层、重复扣次或重复提交。

腾讯云为拟采用方向，具体云开发或云托管、数据库、对象存储、地域、流量与预算待确认。用户提及的“一百级”所指容量或套餐仍待核实；单个存储容量不能代替数据库、运行后端及模型费用。密钥仅服务端管理，测试和生产分离，私有证照与公开媒体分开控制。

最低数据对象包括用户、主体成员、认证审核、资讯媒体、货源字典、订货会登记、客户公开资料、联系回访、额度账本与权益、广告展示配置、门店档案、诊断会话报告、分层知识来源、提示词版本、模型渠道与调用、推荐事件与模型版本、操作日志。

### 16.1 内部批量资料导入

首期主要由内部伙伴上传，入口位于平台电脑运营后台的内容与素材内，不新增用户端一级入口。接收图片、视频、音频、文字、PPT/PPTX、PDF、DOCX和ZIP。厂家和店主已有发布流程继续复用相同素材、任务和审核能力；超大文件先由电脑端处理。

要求支持批量文件队列、并发分片、断点续传、进度和重试。单文件容量目标覆盖300MB、500MB至1GB。任务必须区分“上传”“结构拆解”“OCR/ASR或多模态理解”“归类草稿”“人工确认发布”，分别记录状态、耗时和失败原因。模型、算力、页数和公网带宽影响总时长，不能将容量上限或合成文件传输速度宣传为完整语义理解性能。

PPTX按页、PDF按页、文档按段拆卡；保留原文件、来源、页码、提取文字及可用图片预览。音视频转写、扫描件OCR及图像理解使用实际启用渠道；缺失渠道保留任务并显示待处理。旧版PPT须通过Office兼容转换器处理，不假装已经解码。超过任务页数或展开量上限，需明确提示剩余范围并继续分批处理。

资讯和货源列表均使用双列瀑布流；图片保持合理比例，不把文件原始比例错误地拉伸成统一封面。大字号情况下优先保证阅读和操作完整性。
